# 個股事件時間軸 — 維護方式

本資料夾每檔個股一個檔案，持續累積該標的在 `reports/` 中出現過的事件。
定位是**可長期追加的事實流水帳**，不是一次性的研究筆記（那類放在 `notes/` 根目錄）。

## 資料來源：只看 `reports/`

**唯一來源是 `reports/` 的每日與每週日報**（`YYYY-MM-DD.md`、`weekly_*.md`）。

- **不要掃 `subtitles/`**——字幕檔數量太大，逐檔讀取成本不成比例。日報已是字幕的摘要層，取其結論即可。
- 也不要用 Web 搜尋或模型既有知識補事件；本檔案的價值在於「日報說了什麼」可被回溯查證，混入外部資訊會讓來源欄失效。
- 因此本資料夾必然會漏掉「字幕講過但日報沒收錄」的細節。這是刻意的取捨，不是缺陷；真的需要挖字幕層時，另開 `notes/` 根目錄的主題筆記處理（如 `glass-core-substrate-avgo-goog.md`）。

## 檔案命名

- 美股用 ticker 大寫：`AVGO.md`、`NVDA.md`
- 台股用「代號-名稱」：`2454-聯發科.md`
- 一檔一檔，不要把多個標的塞進同一個檔案；跨標的的主題（如 CPO、玻璃基板）屬於 `notes/` 根目錄的主題筆記

## 新增標的

從既有檔案複製骨架（見下方「檔案結構」），先跑一次全期間掃描：

```bash
cd reports && grep -rn "AVGO\|博通\|Broadcom" 2026-*.md weekly_*.md | grep -v "提及的標的"
```

關鍵字要把**中文名、英文名、ticker** 都列進去，中文頻道與英文頻道用的稱呼不同。

## 更新既有標的

產出新日報後，只掃新增的日期：

```bash
cd reports && grep -rn "AVGO\|博通\|Broadcom" 2026-08-2*.md | grep -v "提及的標的"
```

規則：

1. **只出現在 `- **提及的標的**：` 那行的不收錄**——代表當天只是被列名、沒有實質內容（上面的 `grep -v` 已過濾）。
2. 日期用**日報日期**，事件通常發生在前一交易日或當日盤後；不要自行改成推測的實際發生日。
3. 一件事一列，寫進對應月份表格的末端。同一天多則就多列。
4. 不同頻道對同一件事有不同解讀時，**兩邊都留**，在事件描述裡標註頻道名（如「汪潔民：…」），並把分歧補進「各頻道分歧」表。
5. 數字（財測金額、漲跌幅、股價、目標價）照抄日報，不要四捨五入或換算。
6. 收錄完事實後，回頭更新「一句話現況」「主線敘事」「追蹤中的問題」——**時間軸只記事實，判讀寫在那三節**。
7. 更新檔頭的「涵蓋範圍」與「最後更新」。

## 檔案結構

```markdown
# {名稱} {TICKER} 事件時間軸

**資料來源**：reports/ 每日與每週日報
**涵蓋範圍**：YYYY-MM-DD ～ YYYY-MM-DD
**最後更新**：YYYY-MM-DD
**掃描關鍵字**：`AVGO|博通|Broadcom`

> 相關筆記：[[...]]

## 一句話現況（YYYY-MM-DD）
（兩句話內講完目前處境，每次更新覆寫）

## 時間軸
### YYYY-MM：（該月一句話定調）
| 日期 | 事件 | 來源 |
（重大事件的日期用粗體標記）

## 主線敘事
（貫穿全期間的 2-4 條線，每條一個小標＋兩三句）

## 各頻道分歧（未收斂）
| 議題 | 一方 | 另一方 |

## 追蹤中的問題
- [ ] （後續要盯的變數；確認後打勾並在時間軸補上結果）

---
> **免責聲明**：本筆記為公開資訊之整理，僅供資訊參考，不構成任何投資建議或勸誘。投資涉及風險，過去表現不代表未來結果，請自行評估風險並諮詢合格專業人士意見。
```

## 注意事項

- 字幕是語音辨識產生的，日報裡的公司名、數字可能有誤；明顯離譜的數字標註「（待查）」而非直接採用
- 不做投資建議與方向判斷，只做事件記錄與各方觀點對照
- 「追蹤中的問題」被後續事件回答後，打勾並在時間軸補上該筆事件，保留兩邊的對照
